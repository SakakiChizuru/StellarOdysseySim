# i18n - Internationalization

## Overview

This document describes the internationalization (i18n) system for StellarOdysseySim.

## Architecture

```
i18n.js           ← Core module: t(), tElem(), tMob(), setLanguage()
locales/
  zh.js           ← Chinese translations
  en.js           ← English translations
```

## Translation Keys

All UI text uses `data-i18n` attributes in HTML and translation functions in JavaScript:

| Key Type | Format | Example |
|----------|--------|---------|
| Element display | `ele.{Element}` | `ele.Chemical` → "化学" / "Chemical" |
| Mob name | `mob.{MobName}` | `mob.Brutes` → "蛮兵" / "Brutes" |
| General text | `module.key` | `solodungeons.save_route` → "保存路线" / "Save Route" |

## Usage

### HTML Static Text

```html
<!-- Text content -->
<button data-i18n="solodungeons.save_route">保存路线</button>

<!-- Tooltip -->
<span data-i18n-title="tooltip.save_hint">保存当前路线</span>

<!-- Placeholder -->
<input data-i18n-placeholder="solodungeons.enter_name" />
```

### JavaScript Dynamic Text

```javascript
// Async translation (recommended for async contexts)
const msg = await t('solodungeons.save_empty', { count: 5 });

// Sync translation (after locale is cached)
const msg = tSync('solodungeons.save_empty');

// Element name translation (code values stay unchanged)
const displayName = tElem('Chemical');  // "化学" or "Chemical"

// Mob name translation
const mobName = tMob('Brutes');  // "蛮兵" or "Brutes"
```

### Template Variables

```javascript
// Use {var} in translation strings
await t('solodungeons.confirm_delete', { name: 'My Route' });
// "确定要删除路线 "My Route" 吗？" / "Delete route "My Route"?"
```

```html
<!-- Using data-i18n-n for single numeric variable -->
<span data-i18n="items_count" data-i18n-n="5">5 项</span>

<!-- Using data-i18n-vars for multiple variables -->
<span data-i18n="route_info" data-i18n-vars='{"name":"My Route","count":3}'>
```

## Language Switching

### API

```javascript
// Switch language (async)
await setLanguage('en');  // Switch to English
await setLanguage('zh');  // Switch to Chinese

// Get current language
const lang = getLanguage();  // 'zh' | 'en'
```

### Event Notification

When language changes, a custom event is dispatched:

```javascript
document.addEventListener('languageChanged', (e) => {
    console.log('Language changed to:', e.detail.lang);
    // Re-render dynamic content
    refreshRouteSelect();
    renderPathDetail(...);
});
```

## Module Compatibility

### ES Module Import

```javascript
import { t, tSync, tElem, tMob, setLanguage } from './i18n.js';
```

### Non-Module Scripts (universe_map.js)

Exposed via `window._t`:

```javascript
const msg = window._t('solodungeons.save_empty');
```

## Adding New Translations

1. Add key-value pairs to both `locales/zh.js` and `locales/en.js`
2. Use existing keys as reference
3. Follow naming convention: `{module}.{action}_{noun}`
4. Keep code values (Element, MobName) unchanged; only translate display text

## Fallback Chain

1. Try current language
2. Fallback to Chinese (zh)
3. Return key itself if not found
